# Aplicación móvil

El proyecto incluye clientes para Android e iOS construidos con Capacitor. Comparten la interfaz web y usan un puente nativo para sesión, peticiones autenticadas, eventos y widgets. El código Android integra un widget de inicio; iOS tiene una extensión WidgetKit. El widget presenta una selección limitada de campos y requiere consentimiento y emparejamiento con un servidor compatible.

El cliente móvil está implementado en el repositorio, pero la instalación sencilla de esta beta no configura sus credenciales ni expone la API a la red. El modo local solo escucha en loopback. El acceso desde un teléfono requiere un despliegue remoto con HTTPS y OIDC y la configuración manual de los clientes nativos.

El workflow `verify-ios` construye la app y el widget para el simulador; eso no prueba un iPhone físico. Las builds Android tampoco demuestran que un modelo de teléfono, su widget, permisos y servidor real funcionen juntos. Revisa las ejecuciones de CI del repositorio público y prueba cada dispositivo por separado antes de considerar esa compatibilidad validada. No publiques ni uses APKs configurados para una instalación particular.

El almacén iOS distingue un registro inexistente (`errSecItemNotFound`) de una lectura bloqueada, fallida o inválida. Esos errores impiden confirmar cambios de consentimiento o sustituir permisos; los getters fallan cerrados y se mantiene `WhenUnlockedThisDeviceOnly`. `verify-ios` ejecuta las regresiones del almacén con un Keychain falso, sin leer ni escribir el almacén real del runner. No sustituye las pruebas de bloqueo, protección, widgets, firma o distribución en un teléfono.

El workflow también instala y arranca una build genérica sin configuración en un iPhone 17 Pro Max con iOS 26.5 Simulator. Comprueba el proceso durante cinco segundos, retira únicamente el simulador que ha creado y conserva una captura inicial y un recibo durante siete días. La captura necesita revisión visual. Ese ensayo no autentica un usuario, no ejecuta el widget y no acredita firma, distribución, consumo o comportamiento en teléfonos físicos. No acepta configuración particular del operador ni publica apps compiladas.
## Caducidad al iniciar sesión o enlazar un widget

El backend exige un access token válido con issuer, audiencia, cliente y scopes exactos. Tras comprobarlo mediante introspección y UserInfo protegida, vuelve a validar sus claims con el reloj actual. Si vence durante UserInfo, responde `401` antes de crear la sesión o canjear el código del widget. El rechazo no emite cookie, no crea permisos ni consume el emparejamiento. No añade peticiones al proveedor ni cambia la duración independiente de sesiones y permisos ya concedidos.

Las pruebas con reloj y transporte ficticios cubren el instante anterior, exacto y posterior a la caducidad para app y widget, y ambos endpoints por HTTP. Esta evidencia comprueba el backend; el retorno OAuth, la instalación, los widgets y el uso con una cuenta real necesitan aceptación física.

El renderer posterior corrige un pie cortado en el tamaño compacto y columnas demasiado estrechas en el mediano. ## Widget Android: texto grande y selección de campos

Se corrigió un recorte de datos al usar el texto del sistema al 200%. La distribución respeta las unidades `sp`: con letra grande, el tamaño mediano prioriza el primer campo elegido y el grande dispone los campos en filas. Si el espacio no permite presentar valores junto con origen y antigüedad, muestra «Amplía o abre Pulse» y conserva la acción para abrir la aplicación. Los cuatro tamaños de referencia son 160×90, 180×100, 280×170 y 400×260 dp.

La comprobación usa el APK original instalado en una AVD API34 propia y un AppWidgetHost real, sin cuentas ni coche. Pasan 42 geometrías al 100%, 130% y 200%, sin elipsis ni recortes en las medidas;17 comprobaciones de la caché ejecutada incluyen estados y campos seleccionados. Cubren batería, autonomía, carga, cierre, energía y coste, y ocultan campos no seleccionados. Se revisaron nueve capturas representativas. Las demás capturas no se califican como revisión visual manual completa. La AVD propia se detuvo y sus puertos quedaron libres.

No cambia caché, consentimiento, OAuth, manifest, permisos, dependencias, colores ni backend. Compila offline con Glance1.2 y conserva los37 recursos web del piloto anterior. La selección de distribución se evalúa al renderizar; no garantiza reacción inmediata al cambiar la letra en un widget ya instalado. [Android documenta la escala no lineal hasta 200%](https://developer.android.com/about/versions/14/features#non-linear-font-scaling) y [Glance los tamaños responsive](https://developer.android.com/develop/ui/compose/glance/build-ui).
